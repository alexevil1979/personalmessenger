# План

Каждый этап считается сделанным только после сборки и тех проверок, которые на машине доступны. Незапущенное так и помечается.

## Этап 0 — проектирование

Сделано в этом изменении: пустой каталог, выбор версий, схема, модель угроз, контракт API и план миграции `V1__init.sql`.

## Этап 1 — инфраструктура

Сделано 2026-10-14, с проверками ниже.

- Каркас backend, Android и админки.
- Compose: PostgreSQL 16, Redis 7, `pgsty/silo` как S3-хранилище, Caddy, Coturn, backend, admin.
- Миграция `V1__init.sql`.
- `GET /api/v1/health` проверяет живые PostgreSQL и Redis.
- CI workflow добавлен, на GitHub не запускался: нет входа в `gh` и нет push.

Проверено локально:

- `backend`: `gradlew test` — 5 тестов, 0 падений. Поднимались PostgreSQL 16.15 и Redis, Flyway применил схему, health вернул UP, чужой путь вернул 401, повторная вставка того же сообщения отклонена. `gradlew bootJar` собрал `backend/build/libs/app.jar`.
- `admin-web`: `npm test` — 2 теста. `npm run build` прошёл. В браузере на http://127.0.0.1:5174/ страница показывает ошибку соединения, пока API нет, переключает тему и после «Проверить снова» снова показывает ошибку. Успешный экран со статусом UP в браузере не открывался: долгоживущий backend без Docker здесь не запускался.
- `android`: `testDebugUnitTest` и `assembleDebug` прошли. APK: `android/app/build/outputs/apk/debug/app-debug.apk`. На устройство и эмулятор он не устанавливался.

Не проверялось: `docker compose up`, TLS, Coturn, CI на GitHub, UI-тесты Android на эмуляторе.

## Этап 2 — личность и приглашения

Сделано 2026-10-14 на https://pm.1tlt.ru, версия backend 0.2.0.

- Регистрация только по приглашению, пароль Argon2id, opaque access и refresh.
- Повторное использование отозванного refresh отзывает все сессии этого пользователя.
- Роли owner и admin, список приглашений без кода, код показывается один раз.
- Первый owner создан на сервере через одноразовые переменные окружения. После старта они убраны из `.env` и из контейнера.
- Админка на https://pm.1tlt.ru входит и создаёт приглашение.

Проверено:

- `backend`: `gradlew test` — 10 тестов, 0 падений (health, схема, журнал, вход, приглашение, регистрация, ротация refresh, чужая сессия). `gradlew bootJar` собрал jar.
- `admin-web`: `npm test` — 2 теста, `npm run build` прошёл. В браузере на https://pm.1tlt.ru страница показывает UP 0.2.0, вход owner и создание приглашения.
- Публичный health: postgres, redis и minio UP. WebSocket и E2EE — NOT_ENABLED. HTTP `pm.1tlt.ru` уходит на HTTPS. Сайт `1tlt.ru` по HTTP по-прежнему отвечает 301 на HTTPS.

Android 0.2.0: на том же экране есть вход и регистрация по приглашению. Токены пишутся в зашифрованные настройки. `testDebugUnitTest` и `assembleDebug` прошли. APK: `android/app/build/outputs/apk/debug/app-debug.apk`. На устройство и эмулятор он не устанавливался: подключённых устройств нет.

Не сделано: смена пароля, CI на GitHub. E2EE нет.

## Этап 3 — личный чат

Сделано 2026-10-14, версия backend 0.3.0.

- Личный чат один на пару пользователей. Сообщение пишется в PostgreSQL как открытый текст (`encryption = none`).
- Повтор того же `clientMessageId` не создаёт вторую строку.
- Чужой чат отвечает 404.
- WebSocket `/api/v1/ws` отдаёт новое сообщение участникам. После офлайна клиент забирает `seq` больше курсора.
- Android 0.3.0 хранит чаты и сообщения в Room и показывает, что сервер может прочитать текст.

Проверено: `gradlew test` — 13 тестов, 0 падений, включая уникальный чат, дедупликацию, запрет чужому и доставку в WebSocket. `testDebugUnitTest` и `assembleDebug` прошли. APK не ставился на устройство.

На сервере https://pm.1tlt.ru health 0.3.0: websocket UP, e2ee NOT_ENABLED. Несуществующий собеседник отвечает `404`. `wss://pm.1tlt.ru/api/v1/ws` поднимается и присылает `ready`. Для этого в vhost `pm.1tlt.ru` добавлен прокси WebSocket только на `/api/v1/ws`. Сайт `1tlt.ru` открывается.

## Этап 4 — группы и вложения

Группы сделаны 2026-10-14, версия backend 0.4.0.

Вложения сделаны 2026-10-15, версия backend 0.5.0. Файл принимается только после проверки содержимого и кладётся в MinIO. Ссылка на скачивание действует 5 минут. Аудиофайл сохраняется как голосовое сообщение.

Запись с микрофона — версия 0.5.1. Клиент пишет AMR-WB до 60 секунд. Сервер узнаёт формат по заголовку `#!AMR-WB`. E2EE нет.

- Группа создаётся с названием. Создатель — `owner`.
- `owner` и `admin` добавляют участников. Участник с ролью `member` получает 403. Кто не в группе, видит 404.
- Сообщения группы хранятся открытым текстом, как личный чат.
- Android 0.5.0 умеет создать группу, добавить участника, отправить изображение, PDF или аудиофайл и открыть временную ссылку.

Проверено локально: `gradlew test` — 15 тестов, 0 падений. Отдельный тест грузит PNG, отклоняет HTML и слишком большой файл, запрещает повторное использование вложения и ждёт, пока ссылка истечёт. `testDebugUnitTest` и `assembleDebug` прошли. APK не ставился на устройство.

На сервере https://pm.1tlt.ru health 0.6.5: сообщения открытым текстом, e2ee NOT_ENABLED. Android 0.6.5 показывает «в сети» или время последнего визита и две галочки, когда собеседник прочитал сообщение.

E2EE нет.

## Этап 7 — админка, начато в 0.6.0

Смена пароля, блокировка человека, выход из группы, исключение участника, курсор прочтения и список людей со статусом `blocked` выложены 2026-10-15. Аудит пишется в таблицу, отдельного экрана аудита нет.

## Этап 5 — E2EE

libsignal между двумя устройствами, ключи на клиенте, проверка отпечатка. Этап не закрывается, пока живой обмен шифротекстом не проверен. До этого продукт не называется E2EE.
