# Решения

Дата фиксации: 2026-10-14. Версии ниже совпадают с файлами сборки.

## Backend — Spring Boot 4.1.1 на Java 17

Ветка 3.5 получила последний открытый выпуск 3.5.16 в июне 2026 и больше не находится на OSS-поддержке. Актуальная открытая ветка — 4.1, последний стабильный выпуск на момент выбора — 4.1.1. Она поддерживает Java 17–26. На машине разработки установлен JDK 17, поэтому цель сборки — 17, без требования сразу переходить на 21.

Kotlin 2.3.21 — версия, которую ведёт BOM Spring Boot 4.1.1.

Альтернатива в виде отдельного сервиса на каждый модуль отклонена: для нескольких сотен пользователей это усложнит эксплуатацию без выигрыша в надёжности.

## Хранение

PostgreSQL 16 — основная база. Миграции Flyway, схема является источником истины. Hibernate не подключён: тело сообщения — `bytea`, а запросы синхронизации проще выражать SQL через `JdbcClient` / `JdbcTemplate`. Это решение действует с этапа 2, когда появятся репозитории.

Redis 7 — сессии сигнализации, присутствие и короткие блокировки. Постоянные сообщения в Redis не кладутся.

Файлы — S3-совместимое хранилище. Официальный образ `minio/minio` в октябре 2026 снят с Docker Hub, а анонимная загрузка с Quay отвечает 401. Для Compose выбран публичный образ `pgsty/silo:RELEASE.2026-09-16T00-00-00Z`: это сборка MinIO с теми же переменными `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` и проверкой `/minio/health/live`. Сам образ в этой среде не скачивался, потому что Docker не установлен. Бакет и загрузка файлов ещё не реализованы. Большие объекты в PostgreSQL не пишутся.

## Безопасность доступа

Пароли: Argon2id через `Argon2PasswordEncoder` Spring Security, когда появится регистрация. Сейчас входа нет.

Сессии: случайный refresh-токен, в базе только его хеш, ротация при обновлении, отзыв по устройству и «выйти везде». Access-токен короткоживущий. Это контракт этапа 2, не текущее поведение.

API без cookie-сессии. CSRF отключён, потому что браузер не аутентифицируется cookie. Если позже появится cookie, CSRF включается вместе с ней. Админка ходит в тот же origin через reverse proxy.

Секреты не имеют значений по умолчанию. Вне профиля `test` процесс не стартует, если `DB_PASSWORD` или `REDIS_PASSWORD` короче 12 символов или входит в короткий список заглушек.

## Личный текст — X25519 и AES-GCM, не Signal

Протокол Signal не подключён: зависимость `libsignal` тянет AGPL-3.0, и этот срез её не берёт. Личный текст шифруется на телефоне: эфемерный X25519 плюс статический X25519 ключей устройств, HKDF-SHA256 и AES-GCM. Сервер хранит байты и не видит текст. Отправитель не может расшифровать свой ящик заново, поэтому открытый текст остаётся в Room. У получателя нет секретности на будущее относительно долгоживущего ключа устройства. Группы, файлы и голосовые остаются `encryption = none`, и это написано в приложении и в health (`e2ee: PARTIAL`).

## Звонки

Личный звонок: WebRTC, ICE, STUN и TURN через Coturn с временным секретом `use-auth-secret`. DTLS-SRTP шифрует медиа между телефонами. TURN ретранслирует уже зашифрованные пакеты и видит IP и объём. Сервер видит сигнализацию и запись звонка. Групповых звонков нет.

## Android

`minSdk` 26 (Android 8.0). С этого уровня есть каналы уведомлений, предсказуемая работа с фоновыми ограничениями и нормальный Android Keystore. WebRTC доступен и раньше, но устройства ниже 8 в 2026 году для закрытого сообщества не являются целевыми. `compileSdk` и `targetSdk` — 35, потому что установлены platform 35 и build-tools 35. Platform 36 установлен, build-tools 36 — нет.

DI: Hilt. Локальная база Room появится на этапе 3 вместе с кешем сообщений. Push: FCM, для устройств без Play Services зарезервирован UnifiedPush в схеме `push_tokens.provider`.

## Админка

React 19.3, TypeScript 5.9, Vite 8, MUI 9, TanStack Query 5. TypeScript 7 на момент сборки ещё публикуется как dev-линейка, поэтому зафиксирована стабильная 5.9.

## Инфраструктура

Docker Compose, Caddy, Coturn. Kubernetes, Kafka и отдельный брокер не используются. PostgreSQL, Redis и MinIO публикуются только на `127.0.0.1`. Наружу на первом сервере нужны 80/443 и порты TURN 3478 плюс диапазон реле 49160–49200.

Целевой hostname: `pm.1tlt.ru`. Учётные данные сервера в репозиторий не записываются.
